## Заголовок потока

Поток диалога состоит из двух частей: заголовка и самой структуры диалога.
В заголовке обозначена длина структуры (длина второй части).

Тот же принцип построения заголовка используется и для потока Main Metadata
Stream.

- Если поток помещается в 256 байт, то размер заголовка будет 1 байт. И этот
  байт — размер всего потока минус 1.
- Если поток помещается в размер 65535 (0xFFFF), то заголовок будет состоять
  из 3 байт: первый FF (255), а потом размер всего потока минус размер
  заголовка в байтах с обратным порядком следования шестнадцатеричных байт.
  То есть 2 байта. Всего 3 байта. Например, при размере всего потока 29822
  (0x747E) байт в заголовке будет следующее: 0xFF, 0x7B, 0x74 (то есть
  0x747E-3=0x747B).
- Если же структура состоит из большего числа, нежели помещается в эти два
  байта (>65535), то заголовок будет состоять из 7 байт. Это первые три байта
  0xFF,0xFF,0xFF, а потом тот же самый размер всего потока минус 7 байт
  заголовка с обратным порядком следования шестнадцатеричных байт. Например,
  при размере потока 267151 (0x4138F) заголовок будет такой: 0xFF, 0xFF,
  0xFF, 0x88, 0x13, 0x04, 0x00 (то есть 0x4138F-7=0x41388).

Таблица с примерами диалогов с пограничными значениями длин:

| Размер формы | Размер потока | Заголовок (байт) | Начало потока (*) |
| ---: | ---: | ---: | --- |
| 254 | 255 | 1 | `FE 7B 22` |
| 255 | 258 | 3 | `FF FF 00 7B 22` |
| 256 | 259 | 3 | `FF 00 01 7B 22` |
| 2558 | 2561 | 3 | `FF FE 09 7B 22` |
| 2559 | 2562 | 3 | `FF FF 09 7B 22` |
| 2560 | 2563 | 3 | `FF 00 0A 7B 22` |
| 65533 | 65536 | 3 | `FF FD FF 7B 22` |
| 65534 | 65541 | 7 | `FF FF FF FE FF 00 00 7B 22` |
| 65535 | 65542 | 7 | `FF FF FF FF FF 00 00 7B 22` |
| 65536 | 65543 | 7 | `FF FF FF 00 00 01 00 7B 22` |

(*) `7B 22` — это `{"`, т.е. начало формы (`{"Dialog",`).

## Дополнительные флаги

*Примечание (2026).* Дополнительные флаги — это стиль окна Windows
(dwStyle) элемента. Старшие биты общие для всех окон: 0x50000000 =
WS_CHILD | WS_VISIBLE, 0x00010000 = WS_TABSTOP, 0x00020000 = WS_GROUP
(«первый в группе»), 0x00800000 = WS_BORDER, 0x08000000 = WS_DISABLED.
Младшие 16 бит — стили класса: BS_ для кнопок, флажков, переключателей, рамок
группы и картинок (BS_AUTOCHECKBOX = 3, BS_AUTORADIOBUTTON = 9,
BS_OWNERDRAW = 0xB, BS_LEFTTEXT = 0x20), SS_ для надписей (SS_ETCHEDHORZ =
0x10, SS_ETCHEDVERT = 0x11, SS_ETCHEDFRAME = 0x12), ES_ для полей ввода
(ES_PASSWORD = 0x20, ES_CENTER = 1, ES_NUMBER = 0x2000), CBS_ для полей со
списком, LBS_ для списков, TVS_ для деревьев. GComp 3 выгружает их в
свойство ДопФлаги именами WinAPI, например `SS_RIGHT, WS_VISIBLE, WS_CHILD`.

## Горячая клавиша

Формат: `"{""<Модификатор>"",""<Скан-код>""}"`

Модификатор может быть bit OR комбинацией 3-х значений:

| Клавиша | Двоичное | Шестнадцатеричное |
| --- | ---: | ---: |
| Shift | 111 | 0x07 |
| Ctrl | 1011 | 0x0b |
| Alt | 10011 | 0x13 |

Иногда встречается модификатор со значением 0x03 (в комплексной 7.70.451).
Зачем это нужно — непонятно. 1С воспринимает это как отсутствие
модификаторов.

Скан-код — он и есть скан-код.

*Примечание (2026).* Модификатор — поле fVirt структуры Windows ACCEL:
FVIRTKEY = 0x01, FNOINVERT = 0x02, FSHIFT = 0x04, FCONTROL = 0x08, FALT =
0x10. Поэтому 0x03 — клавиша без модификаторов. Второе число — не скан-код,
а код виртуальной клавиши (VK_*), так как установлен FVIRTKEY.

## Идентификатор картинки

Идентификатор картинки из 41-го параметра контрола рассчитывается не просто,
а очень просто. Идём в папку PictureGallery. Находим нужную картинку. Её
имя — это что-то вроде `__Picture.NNNNNNN.ext`, где NNNNN — некоторое
16-ричное число, а ext — расширение. Так вот, если преобразовать 16-ричное
число в 10-ричное — получим идентификатор из формы.
